# I2V Exchange — End-to-End Quality Matrix (Full Vision)
**Do not certify production readiness without real integrated services, manual user testing and security/performance review.**

| Flow | Demo acceptance | Integrated acceptance | Critical negative test |
|---|---|---|---|
| Public discovery | Projects, sector sorting, filter and load states | Search projection matches published records | Private draft appears in suggestions |
| Startup leaderboard | Seeded metric histories, transparent ranking policy | Policy snapshots reproducible and timed | Self-likes/paid promotion inflate performance |
| Watchlist | Save, unsave, update preference | Persist and send opt-in messages | Revoked project leaks private status |
| Student creator | Account, draft, privacy preview, public profile | Auth + files + object ACL + indexes | Public link exposes private research |
| University operator | Claim organization, create showcase | Verification and org permissions | University admin reads all student work |
| Lab supplier | Publish facility/capacity, accept inquiry | Confirmed verification, booking/notification | Unqualified lab falsely marked verified |
| Equipment/materials vendor | Add inventory, quote, manage requests | Provider data and payment/fulfillment integrations | Hazardous item auto-approved; false stock |
| Manufacturer/pilot | Submit capability, invite founder | Negotiated terms and evidence workflow | Supplier receives secret CAD without consent |
| Competitions | Enter, eligibility, assign judges, results | Live shared state and audit | Conflict judge scores related project |
| Pitch Arena | Simulated rooms, Q&A, panel score | Real calls/reconnect/recording/consent | Unauthorized spectator joins private room |
| Networking | Intro request, decline, block | Deliver with rate limits and audit | Repeated blocked sender bypasses limits |
| AI Intelligence | Clearly fictional example with source-shaped claims | Cited live research, retrieval boundary tests | Prompt injection leaks private data |
| Graduation | Segment paths, award, alumni page | Audit-based verification, ongoing reports | Closed company remains misrepresented active |
| Capital readiness | Demo **non-executable** user journey | Only with legal approval and licensed partner | Mock buy/sell action causes real transfer |

### Test evidence required
Each feature in `FEATURE_REGISTRY.md` must link to actual tests run; capture environment, version, known limitations, demo-vs-live status, screenshots/video where useful, accessibility outcomes, security cases and unresolved provider dependencies. Do not check 'done' solely because Expo Go renders the UI.

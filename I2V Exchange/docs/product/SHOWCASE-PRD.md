# PRD — Project Showcase, Creator Identity, Discovery and Milestones

## Product heart
A public project page should make an authentic student-built innovation feel as compelling as a product launch while staying precise about maturity, sources and opportunities. This is the **anchor** for all events, missions, achievements, AI assistance and partner discovery.

## Project categories
Research | Software | Hardware | AI/ML | Industrial/process invention | Scientific method | Creative technology | Registered startup | Other. Allow mixed tags. `project` is not synonymous with incorporated `company`.

## Creator flow
Choose category -> enter working title and problem -> describe current implementation/solution -> assign maturity stage (with examples) -> upload approved cover/demo -> declare authors/team and university *claim* -> specify what help is needed -> attach optional protected evidence -> review **public vs confidential** preview -> publish -> obtain shareable page -> update milestones/CTA.

## Public profile components
- Striking real visual hero; short human-readable proposition; latest development update; industry/stage tags.
- Problem -> build/demo -> evidence highlights -> project needs; expandable method only if public.
- Creator identity and exact claim level: self-declared, institution-verified, independently tested, etc.
- Progress timeline: status of milestones with source labels; upcoming demo/challenge participation.
- Action area: follow, request demo, offer mentorship/skill, contact via consented introduction.
- Suggested related projects via transparent relevance and user controls; not fabricated valuations.
- Appropriate social metadata/preview generated from **public content only**.

## Milestone rules
- A milestone records type, date, narrative, evidence pointers, author, visibility and `claim_status`.
- `achieved_at` may be claimed by founder; `verified_at` exists only upon independent confirmation with reviewer/issuer/criteria.
- Deletion is a new redaction/correction event; source version hashes and authorized access logs remain according to retention policy.
- History should show substantial movement, not incentivize filler updates.

## Creator safety
- Warn before disclosing potentially patentable implementation, unpublished documents or partner/client names.
- Preview link must be time-bound/permissioned if private; avoid speculative preview assets in public CDN.
- Public publishing is explicit per version; changing an image's privacy is separate from changing profile visibility.
- Team permissions distinct from creator ownership; university supervisors not automatically administrators of student projects.

## Discovery relevance
- Organic ranking based on stated user interests, category, recency of meaningful approved updates, public completeness and transparent editorial rules.
- No monetized stealth priority; paid placements labeled; don't turn popularity into a false merit or commercial value score.
- Browse without account, request contact requires account; ID verification only when proportionate to the action.

## Tests
- Private draft does not appear in search, OpenGraph metadata, feeds, suggestions or object links.
- Public project does not imply publication of every attached evidence item.
- Broken media / slow network leaves a readable project page and CTA.
- Project relabeling / slug changes do not break event references or provenance identity.
- Introducing corrected credit/ownership claims updates public display while retaining legitimate audited history.

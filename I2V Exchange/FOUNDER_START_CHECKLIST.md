# I2V Exchange — Founder Go/No-Go Checklist for Starting Codex

### Ready to start building (no other API accounts required yet)
- [ ] Private GitHub repo created and this ZIP fully extracted at its root (keep hidden `.agents/skills` folders).
- [ ] Codex has repo access, read `CODEX_MASTER_DIRECTIVE.md` and `AGENTS.md`.
- [ ] Codex confirms four new requirements: exchange-style data UX, scoped startup rankings, multi-role signup, lab/equipment/material providers.
- [ ] Codex sets up real Expo app + mobile design system, and exposes a local Expo Go preview; asks only for essential setup actions.
- [ ] Codex logs tested implementation status rather than calling mocked screens production-ready.
- [ ] No paid external subscriptions or production actions authorized yet.

### What to see in the demo app before accepting design quality
- [ ] Attractive human-designed Discover feed, featured real-looking **fictional** project stories, progress charts with explicit sources and a watchlist.
- [ ] Useful sector explorer, startup comparison and transparent top-performing categories.
- [ ] Easy account-role choices, including supplier and lab provider, with an add-role flow later.
- [ ] Supplier can draft/publish equipment/material listings and reply to a fictional startup inquiry.
- [ ] Lab provider can list capacity and respond to a test/facility booking inquiry.
- [ ] Student can create a project, submit to competition, request a mentor and view pitch arena.
- [ ] Consistent light/dark themes, 360px/desktop navigation, accessible charts, error/empty/retry states.
- [ ] Capital/investment features presented only as future non-live pathways until authorized.

### When Codex reports completion
Request evidence for actual tests, working screens, service contracts, documented gaps, provider connection steps, security and role isolation tests, video and AI limitations, and accurate launch readiness. Remember: no ZIP of specifications is already a deployed platform.
